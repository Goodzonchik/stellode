# Диаграммы на фронтенде (ui-spec §5)

Кратко о том, как SPA отражает [ui-spec §5.0](./frontend/ui-spec.md): **обзорные** и **версионные** режимы — это проекция данных на холсте, модель графа в Neo4j не меняется.

## Обзорные диаграммы

Маршруты вида `/units/:id/diagram`, `/teams/:id/diagram`, `/services/:id/diagram`, `/components/:id/diagram`, а также **cross-unit** (`/units/:id/diagram/cross-unit`). Самостоятельной обзорной `/applications/:id/diagram` **нет** (редирект на состав `…/versions/current/diagram`, [ui-spec §5.3.2](./frontend/ui-spec.md)).

- После загрузки `ArchitectureGraph` для team / service / component / feature-version: сначала [`projectComponentVersionsToComponents`](../apps/frontend/src/pages/diagrams/project-component-versions-to-components.ts) (CV → `Component` «Имя · версия», id = CV), затем [`mergeVersionNodes`](../apps/frontend/src/pages/diagrams/merge-version-nodes.ts) **без** схлопывания `componentVersion` (только `ApplicationVersion` / при необходимости `featureVersion`). Для **`/units/:id/diagram`**: [`projectUnitOverviewDiagram`](../apps/frontend/src/pages/diagrams/project-unit-overview-diagram.ts) (убирает Unit и инцидентные рёбра, фильтрует `DEPENDS_ON`, схлопывает CV→обзорный Component, строит виртуальные `USES` с лейблом `USES`, `relationshipType` остаётся `USES_COMPONENT_VERSION` для grouping по `applicationId`), затем `mergeVersionNodes` с `overviewVersionMergeConfig`. Диаграмма **команды**: после merge — [`clearFeatureDraftVersionFields`](../apps/frontend/src/pages/diagrams/clear-feature-draft-version-fields.ts) (на ноде Feature только active), затем [`hideTeamDiagramAnchor`](../apps/frontend/src/pages/diagrams/hide-team-diagram-anchor.ts) (нода `Team` и инцидентные рёбра, в т.ч. `MAINTAINS`, `hidden`; имя для заголовка — из сырого `ArchitectureGraph`), затем UI-only [`applyTeamDiagramCodeOnlyVisibility`](../apps/frontend/src/pages/diagrams/apply-team-diagram-code-only-visibility.ts) при чекбоксе **«Только код»**; impact **`on-prod`**; меню холста — «Создать компонент», без «Добавить компонент».
- **Легенда фильтров**: `/units/:id/diagram` — instance-фильтр ([`UnitDiagramInstanceFilters`](../apps/frontend/src/pages/diagrams/UnitDiagramInstanceFilters.tsx), пайплайн [`layoutUnitDiagram`](../apps/frontend/src/pages/diagrams/layout-unit-diagram.ts) / [`projectUnitDiagramVisibleGraph`](../apps/frontend/src/pages/diagrams/project-unit-diagram-visible-graph.ts); каталог из первого GET; сверху — [`DiagramScopeTabs`](../apps/frontend/src/pages/diagrams/DiagramScopeTabs.tsx)). `/components/:id/diagram` — чекбоксы типов ([`applyComponentDiagramVisibility`](../apps/frontend/src/pages/diagrams/component-diagram-type-visibility.ts)) + [`layoutVisibleDiagram`](../apps/frontend/src/pages/diagrams/layout-visible-diagram.ts) (ELK). `/teams/:id/diagram` — UI-only чекбокс **«Только код»** ([`TeamDiagramLegend`](../apps/frontend/src/pages/diagrams/TeamDiagramLegend.tsx), default off; при вкл. — скрытие `Service`/`Feature` через [`applyTeamDiagramCodeOnlyVisibility`](../apps/frontend/src/pages/diagrams/apply-team-diagram-code-only-visibility.ts); легенда [`getLegend`](../apps/frontend/src/pages/diagrams/get-legend.ts) без секций Функционалы/Услуги; без URL; сброс при смене `:id`; раскладка [`layoutVisibleDiagram`](../apps/frontend/src/pages/diagrams/layout-visible-diagram.ts) без `fitView`). `/feature-versions/:id/diagram` — не полный набор type-чекбоксов: только UI-only **«Команды»** через [`applyFeatureVersionDiagramVisibility`](../apps/frontend/src/pages/diagrams/feature-version-diagram-type-visibility.ts) (`teamsVisible`) и [`layoutFeatureVersionDiagram`](../apps/frontend/src/pages/diagrams/layout-feature-version-diagram.ts). Базовые refs (`unit`/`team`/`component`/`feature-version`) хранят **плоский** граф до группировки. На [`CrossUnitDiagram`](../apps/frontend/src/pages/diagrams/CrossUnitDiagram.tsx) чекбоксов типов **нет**; ноды `Unit` на cross-unit **сохраняются**.
- Актуальная и черновая версии попадают в поля ноды (`actualVersion` / `draftVersion`), см. [`CustomNode`](../apps/frontend/src/pages/diagrams/CustomNode.tsx); на team-диаграмме у Feature `draftVersion` снимается после merge ([ui-spec §5.3.1](./frontend/ui-spec.md)).
- [`architectureGraphToDiagram`](../apps/frontend/src/common/architecture-graph-to-diagram.ts) отдаёт **плоские** ноды (без `parentId`); `applicationId` у `USES_COMPONENT_VERSION` и `status` у `HAS_COMPONENT` переносятся в `ViewEdge`. Слияние [`mergeVersionNodes`](../apps/frontend/src/pages/diagrams/merge-version-nodes.ts) дедуплицирует рёбра с учётом `applicationId`; для `HAS_COMPONENT` при схлопывании нескольких версий выбирается `active`, иначе `deprecated`.
- **Рёбра `DEPENDS_ON` на холсте:** перед React Flow [`prepareDependsOnCanvasEdges`](../apps/frontend/src/pages/diagrams/prepare-depends-on-canvas-edges.ts) ставит `type: 'dependsOn'`, `markerEnd` (стрелка consumer→provider) и при паре `A→B`/`B→A` — противоположный `pathOffset`; рендер — [`DependsOnEdge`](../apps/frontend/src/pages/diagrams/DependsOnEdge.tsx) (`edgeTypes` в общем [`DiagramCanvas`](../apps/frontend/src/pages/diagrams/DiagramCanvas.tsx) для [`Diagrams`](../apps/frontend/src/pages/diagrams/Diagrams.tsx) и [`CrossUnitDiagram`](../apps/frontend/src/pages/diagrams/CrossUnitDiagram.tsx)). Остальные типы рёбер без стрелок и без спец-смещения; синтетические `CROSS_UNIT_LINK` не трогаются. UI — [ui-spec §9.0](./frontend/ui-spec.md).
- [`getLayoutedElements`](../apps/frontend/src/pages/diagrams/layout-diagram.ts) — **асинхронная** раскладка **ELK** (`elkjs`, алгоритм `layered`, `hierarchyHandling: INCLUDE_CHILDREN`); на каждый вызов строится новый граф ([`build-elk-graph`](../apps/frontend/src/pages/diagrams/build-elk-graph.ts)), размеры листьев оцениваются по данным ноды ([`estimate-view-node-dimensions`](../apps/frontend/src/pages/diagrams/estimate-view-node-dimensions.ts)), координаты детей относительны родителю ([`apply-elk-layout`](../apps/frontend/src/pages/diagrams/apply-elk-layout.ts)). Устаревшие результаты раскладки отбрасываются ([`useLatestRequestGuard`](../apps/frontend/src/hooks/useLatestRequestGuard.ts)). **Гонки hub-загрузки:** перекладка по visibility/impact делит тот же `useLatestRequestGuard` с полной загрузкой графа; пока load in-flight, кэшированные плоские base (`unit`/`team`/`component`/`feature-version`) должны быть **`null`** (сброс **до** `await` API в `loadDiagrams`), иначе `beginLayoutRequest` отбросит in-flight load — перекладка пропускается, пока base === `null`. На странице [`Diagrams`](../apps/frontend/src/pages/diagrams/Diagrams.tsx) после **успешной загрузки** графа с API выполняется `fitView`; это **не** дублируется при смене instance-фильтров на unit-диаграмме и при перекладке LR/TB (ui-spec §5.3).

## Subflow Application (контейнеры)

На диаграммах `unit`, `team`, `service`, `feature-version`, `component` и в деталях cross-unit bridge компоненты группируются внутри приложений ([`groupNodesByApplication`](../apps/frontend/src/pages/diagrams/group-nodes-by-application.ts)):

- Контейнер — нода `Application` (тип React Flow `group`, компонент [`GroupNode`](../apps/frontend/src/pages/diagrams/GroupNode.tsx)); `ApplicationVersion` **схлопывается** в контейнер, версия выводится в заголовке «Имя · версия». Контейнер без детей остаётся обычной нодой `custom`.
- Дети — `Component` (спроецированные с CV) по `HAS_COMPONENT` **и/или** `USES.applicationId`. Узел в нескольких приложениях **дублируется** (`appId::nodeId`, `data.sourceId` / `applicationId` / `applicationStatus`); при `memberships.size > 1` на копии — `data.duplicate: true`, в UI метка **`duplicate`** в рамке ([`CustomNode`](../apps/frontend/src/pages/diagrams/CustomNode.tsx)).
- `HAS_COMPONENT` и `HAS_VERSION` к схлопнутой AV **не рисуются**. `USES` с `applicationId` ведёт в нужную копию.
- Контекстное меню, impact и connect — по исходному id ([`resolveSourceNodeId`](../apps/frontend/src/pages/diagrams/resolve-source-node-id.ts)).
- ПКМ **«Открыть в списке»**: целевой id и путь — [`resolveOpenInListTarget`](../apps/frontend/src/pages/diagrams/resolve-open-in-list-target.ts) (для CV → `componentId` родителя по `HAS_VERSION`/`HAS_DRAFT`; показ только если `unitId` сущности = UnitContext); UX — [ui-spec §5.2.1](./frontend/ui-spec.md). На cross-unit — обзор и drill-down.
- Обзор cross-unit — ELK **без** группировки.
- **Bridge (drill-down):** после `groupNodesByApplication` — [`groupBridgeNodesByUnit`](../apps/frontend/src/pages/diagrams/group-bridge-nodes-by-unit.ts): оба `Unit` пары → `group`; `Team` / `Service` / `Feature` / `Application` получают `parentId` Unit (`unitId` или fallback по `HAS_TEAM` / `PROVIDES` / `OWNS`); Component без App-membership удаляется; затем [`filterBridgeUnitStructuralEdges`](../apps/frontend/src/pages/diagrams/filter-bridge-unit-structural-edges.ts) скрывает `HAS_TEAM` / `PROVIDES` / `OWNS`. Цвет рамки Unit — HSL из FNV-хеша `data.unitId` ([`unit-group-accent`](../apps/frontend/src/pages/diagrams/unit-group-accent.ts)); **подробнее в** [ui-spec §5.5](./frontend/ui-spec.md).

**Диаграмма юнита** ([ui-spec §5.3](./frontend/ui-spec.md)): нода `Unit` и рёбра к ней вырезаются в `projectUnitOverviewDiagram` (заголовок `Юнит {name}` — из сырого графа до проекции). Сразу после проекции — [`filterUnitCurrentComposition`](../apps/frontend/src/pages/diagrams/filter-unit-current-composition.ts): оставляет Application только с непустым `current`-составом (`HAS_COMPONENT.status ∈ {active, deprecated}`) и Component только из этого состава; membership **не** выводится из `USES.applicationId`; плоских Component у `Team` нет. Далее merge AV → UI-only instance-фильтр: phase1 (team/service/feature/component по `hiddenIds`) → `groupNodesByApplication` → phase2 (скрытые Application и ноды с их `parentId`) → рёбра только между оставшимися нодами → [`filterUnitDiagramCanvas`](../apps/frontend/src/pages/diagrams/filter-unit-diagram-canvas.ts) (без `OWNS` и пустых Application).

## Версионные диаграммы

- **`/feature-versions/:id/diagram`**: данные `GET /api/diagrams/feature-version/:id` ([diagrams-api.md](./diagrams-api.md)); для **draft** API отдаёт `ApplicationVersion(current)`, для **опубликованной** — AV через `PINNED_TO_APPLICATION_VERSION` (без fallback на current; нет pin → Application без AV, caption без «· version», [ui-spec §5.4](./frontend/ui-spec.md)); проекция CV→Component·версия (в т.ч. `dependency`) + merge AV; раскладка [`layoutFeatureVersionDiagram`](../apps/frontend/src/pages/diagrams/layout-feature-version-diagram.ts) — **сначала** `groupNodesByApplication` (пока USES/HAS_COMPONENT и FV ещё в графе), **затем** [`applyFeatureVersionDiagramVisibility`](../apps/frontend/src/pages/diagrams/feature-version-diagram-type-visibility.ts) (скрытие Feature / FeatureVersion / Service, **всех** Unit; Team при `teamsVisible: false`; чужие App/CV и cross-unit `DEPENDS_ON` при `crossUnitLinksVisible: false`); заголовок `Фича {name} {version} ({status})`; легенда — блок версий (draft первым; по умолчанию с Features открывается **active**) и **ниже отдельным блоком** чекбоксы **«Команды»**, **«Связь с другим юнитом»** (default **off**) и **«Сравнить с предыдущей»** ([`FeatureVersionDiagramLegend`](../apps/frontend/src/pages/diagrams/FeatureVersionDiagramLegend.tsx); «Команды» default on, всегда виден; выкл. → только `Team` + `MAINTAINS`; без `fitView`; при переключении версий в легенде teams/cross-unit/compare **сохраняются**, сброс к defaults — при уходе с hub feature-version). Маркер **`?`** на ноде CV (OFF — локальный потребитель; ON — чужая нода) + tooltip Юнит/Команда/Фича/Сервис ([ui-spec §5.4](./frontend/ui-spec.md)). Для **`draft`**: меню холста — «Создать компонент» / «Добавить компонент»; оба требуют App (выбор или create той же формой, что Applications) и bind с `applicationId`; create App доступен и в диалогах DEPENDS_ON / cross-unit. ПКМ по CV в App: «Добавить связь» (same-unit DEPENDS_ON: упрощённый диалог + `POST /edge/depends-on/from-feature-versions`, Select из состава draft), «Связь с другим юнитом», «Исключить из фичи» (`bind-component-versions` `remove`), **«Поднять версию»** (`POST /api/feature-versions/raise-component-version`, [ui-spec §5.4](./frontend/ui-spec.md)); ПКМ по видимому ребру `DEPENDS_ON` — «Удалить связь» (`POST /edge/depends-on/delete`, [ui-spec §9.4](./frontend/ui-spec.md)); drag handles между component/dependency при `nodesConnectable`. Плоские component/dependency без `parentId` — действия блокируются. Старый `/features/:id/diagram` редиректит на версию. Табличный вид той же страницы собирает [`buildFeatureVersionCompositionTable`](../apps/frontend/src/pages/diagrams/build-feature-version-composition-table.ts) из уже разложенных нод — [ui-spec §5.4](./frontend/ui-spec.md#табличный-вид).
- **Сравнение с предыдущей** ([ui-spec §5.4](./frontend/ui-spec.md)): предшественник — `inheritedFromId` из `POST /feature-versions` (Swagger `/api/docs`); при включённом чекбоксе — второй `GET /api/diagrams/feature-version/:inheritedFromId`, клиентский diff множеств состава / `DEPENDS_ON` / Application / Unit, merge графов на одном холсте с `diffStatus` (`added` | `removed`), затем тот же `layoutFeatureVersionDiagram` (с текущими teams/cross-unit flags). Заголовок: `Фича {name} · сравнение {version} ({status}) с {prevVersion} ({prevStatus})`. Read-only; ready, impact и **«Открыть в списке»** скрыты; при переключении версий в легенде compare/cross-unit/teams **сохраняются** (нет `inheritedFromId` → compare off); сброс к defaults — при уходе с hub feature-version.

#### `POST /api/feature-versions/bind-component-versions`

- Доступно для **`FeatureVersion` в статусе `draft`**. Полное множество связей **одним массивом заменять нельзя** — снимаются только явно указанные в `remove`; добавляются — только через `add`.
- Тело (JSON): `featureVersionId` (UUID); опционально `add`, `remove` — массивы `{ componentVersionId, applicationId }` (`componentVersionId` может быть id `Component` с резолвом на бэкенде). Хотя бы один из двух массивов после дедупликации должен быть **непустой**, иначе `400`.
- Пример: добавить одну версию — `{ "featureVersionId": "…", "add": [{ "componentVersionId": "…", "applicationId": "…" }] }`; убрать — `"remove": [{ … }]`; замена версии в составе — одним запросом оба массива (сначала снимется старая, затем добавится новая цель без затрагивания остальных `USES`).
- Повтор той же пары `(componentVersionId, applicationId)` уже в составе этой FV → **`400`**, «Такая версия компонента уже добавлена в это приложение»; при любом дубле в `add` отклоняется **весь** запрос (после `remove` в том же теле). Другие CV и та же CV в другом `applicationId` — допустимы ([spec.md §6](./spec.md); контракт — Swagger `/api/docs`).

#### `POST /api/feature-versions/raise-component-version`

- Автоматизация «Поднять версию» на `/feature-versions/:id/diagram` ([ui-spec §5.4](./frontend/ui-spec.md); контракт — Swagger `/api/docs`): для draft FV заменить `USES` одной пары `(fromComponentVersionId, applicationId)` на более новую CV (создать draft при отсутствии `toComponentVersionId`), синхронизировать исходящие `DEPENDS_ON` с `consumerApplicationId` = этот app и перенести входящие `DEPENDS_ON` этого draft с `providerApplicationId` = этот app. Не пишет `HAS_COMPONENT`.

- **`/applications/:id/versions/:version/diagram`**: не диаграмма — [`ApplicationComposition`](../apps/frontend/src/pages/diagrams/ApplicationComposition.tsx), таблица состава через `GET /application-versions/:id/composition` ([ui-spec §5.3.2](./frontend/ui-spec.md); контракт — Swagger `/api/docs`).

## Hover-подсветка связей (ui-spec §5.3.0)

- На `/units/:id/diagram` и обзоре `/units/:id/diagram/cross-unit`: при наведении на ноду подсвечивается путь 1-го уровня + свой подъём (без dimming графа). Правила, таблица типов и визуал — [ui-spec §5.3.0](./frontend/ui-spec.md) / §5.5; сбор id — [`collect-hover-path-ids`](../apps/frontend/src/pages/diagrams/collect-hover-path-ids.ts).

## Impact на диаграмме (ui-spec §5.2)

- Правый клик по ноде → «Показать влияние» → `GET /api/impact/{segment}/{id}?mode=…` (на **unit**-диаграмме пункт **не** показывается); режим совпадает с [`inferDiagramImpactMode`](../apps/frontend/src/pages/diagrams/diagram-production-overlays.ts).
- Подсветка: объединение `units`, `teams`, `services`, `features`, `applications`, `components`, `consumers`, `providers` из ответа ([`collectImpactHighlightIds`](../apps/frontend/src/pages/diagrams/collect-impact-highlight-ids.ts)).
- Для ноды `FeatureVersion` запрос идёт на **`impact/feature/:featureElementId`** (родительская `Feature` ищется по рёбрам графа).

## Диаграмма сервиса и `AGGREGATES` (ui-spec §5.6, §6)

- Данные: `GET /api/diagrams/service/:id` — прод-подграф (см. [diagrams-api.md](./diagrams-api.md)); вкладка **«Связи»** — маршрут `/services/:id/diagram/integrations` и `GET /api/diagrams/service/:id/integrations`.
- Холст: контекстное меню → «Добавить фичу» / по ноде `Feature` → «Снять фичу» (не показывается для сервиса в статусе `archive`); API — [aggregates-api.md](./aggregates-api.md).
- По умолчанию отображаются только **активные** рёбра `AGGREGATES`; снятые (`deleted: true`) скрыты (ответ API в **режиме `on-prod`**). Полная картина (включая историю) — query **`?projection=draft`**; снятые связи рисуются пунктиром.

## Cross-unit drill-down (ui-spec §5.5)

- Страница [`CrossUnitDiagram`](../apps/frontend/src/pages/diagrams/CrossUnitDiagram.tsx) на маршруте `/units/:id/diagram/cross-unit`: обзор из `GET /api/diagrams/cross-unit?centerUnitId=<id>`. **`id`** — сегмент пути (валидный UUID), иначе fallback на основной юнит из [`UnitContext`](../apps/frontend/src/context/UnitContext.tsx) ([`resolveCrossUnitCenterUnitId`](../apps/frontend/src/pages/diagrams/resolve-cross-unit-center-unit-id.ts)). Если центр не определён — **нет** запроса графа: заглушка и ссылка на **`/units`**. На холсте используется встроенный `fitView` при отрисовке; отдельной подгонки на ноду `Unit` при изменении нод нет (ui-spec §5.5).
- Переключатель **«Юнит» / «Между юнитами»** ([`DiagramScopeTabs`](../apps/frontend/src/pages/diagrams/DiagramScopeTabs.tsx)): `/units/:id/diagram` ↔ `/units/:id/diagram/cross-unit`.
- Клик по ребру `CROSS_UNIT_LINK` → загрузка `GET /api/diagrams/cross-unit/bridge/:unitIdA/:unitIdB` и **второй холст поверх** обзорной диаграммы (оверлей) с обзорной проекцией (CV→Component + merge AV + Application-grouping + **Unit-grouping**), с контекстом команд, сервисов, фич и приложений с бэкенда; закрытие — крестик в правом верхнем углу оверлея. Вложенность Unit — только SPA ([`layoutVisibleDiagram`](../apps/frontend/src/pages/diagrams/layout-visible-diagram.ts) при `crossUnitBridge`); ответ API без изменений. Фильтры в легенде под [`DiagramScopeTabs`](../apps/frontend/src/pages/diagrams/DiagramScopeTabs.tsx) ([`CrossUnitBridgeLegend`](../apps/frontend/src/pages/diagrams/CrossUnitBridgeLegend.tsx)), только при открытом bridge; [`applyCrossUnitBridgeVisibility`](../apps/frontend/src/pages/diagrams/apply-cross-unit-bridge-visibility.ts) — **после** Application/Unit grouping в [`layoutVisibleDiagram`](../apps/frontend/src/pages/diagrams/layout-visible-diagram.ts); без повторного API.
