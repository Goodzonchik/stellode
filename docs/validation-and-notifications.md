# Warnings, блокировки и уведомления

Описание предупреждений (`warnings[]`), классификации консистентности графа (**Warning/Critical**), правил блокировок и уведомлений.

---

## Связи `DEPENDS_ON` между `ComponentVersion`

Полная матрица допустимых пар статусов. Столбец «При наследовании» — поведение при копировании `DEPENDS_ON` в новый черновик компонента (версия со статусом **`draft`**, см. `spec.md` §4). Столбец «В прод-проекции» — трактовка существующего ребра в **режиме `on-prod`** (см. `spec.md` §10).

| Источник → цель | При создании | При наследовании | В прод-проекции (режим `on-prod`) |
| --------------- | ------------ | ---------------- | ----------------------------- |
| `draft → draft` | Допустимо | Допустимо | — (`draft` вне прод) |
| `draft → active` | Допустимо | Допустимо | — |
| `draft → deprecated` | **Warning** | Допустимо | — |
| `draft → unactive` | **Запрещено** (см. `spec.md` §4.1) | Допустимо; при публикации — обязательное предупреждение | — |
| `active → draft` | **Warning** | Допустимо | **Warning** |
| `active → active` | Допустимо | Допустимо | Допустимо |
| `active → deprecated` | **Warning** | Допустимо | **Warning** |
| `active → unactive` | **Запрещено** (см. `spec.md` §4.1) | Не встречается | **Critical** (аномалия) |
| `deprecated → draft` | **Warning** | Допустимо | **Warning** |
| `deprecated → active` | Допустимо | Допустимо | Допустимо |
| `deprecated → deprecated` | **Warning** | Допустимо | **Warning** |
| `deprecated → unactive` | **Запрещено** (см. `spec.md` §4.1) | Не встречается | **Critical** (аномалия) |
| `unactive → *` | Не применимо — редактирование `DEPENDS_ON` у `unactive`-версии запрещено (см. `spec.md` §3.3.2) | Не встречается | Исторический след, вне прод-проекции |

Запрещённые сочетания с **`unactive`** как целью для **новых** связей — см. `spec.md` §4.1 (новые связи на `unactive` не создаются).

### 9.x. Представление предупреждений (warnings)

- **Warning** по таблице выше является частью консистентности графа и используется UI/impact-валидацией.
- При создании или анализе связи система возвращает массив `warnings[]` (код + сообщение), **не изменяя** факт выполнения операции, если в спецификации нет явного запрета.
- Если операция вернула `warnings[]`, UI обязан показать **блокирующее предупреждение** с явным подтверждением пользователя (**ack**) перед завершением действия. При этом **backend-физически не блокирует** выполнение операции по причине `Warning`.

## Консистентность и блокировки

- **Warning** — класс предупреждений, при котором операция **не блокируется на backend**; перечень пар статусов `DEPENDS_ON` и соответствующих уровней — [таблица выше](#связи-depends_on-между-componentversion).
- **Critical** — класс, при котором операция **блокируется на backend** явным запретом; показ пользователю обязателен; фиксация в audit. Полный список запретов — `spec.md` §3.2, §4.1, §5.1, §5.2, §6.
- Публикация пустого `FeatureVersion(draft)` (нет исходящих `USES_COMPONENT_VERSION`) — **Critical**: backend отвечает **`400`**, сообщение «Нет связанных компонентов» (**см. §6**).

Отдельное правило UI: если операция вернула `warnings[]`, UI требует явный **ack** перед завершением действия (см. [§9.x](#9x-представление-предупреждений-warnings)).

## Уведомления

- **Warning**:
  - уведомление/предупреждение показывается в UI;
  - если операция вернула `warnings[]`, требуется явный **ack** в UI (см. [§9.x](#9x-представление-предупреждений-warnings));
  - `Warning` **не** является причиной backend-блокировки операции.
- **Критичные / обязательные**:
  - соответствуют классу **Critical** (см. [§ «Консистентность и блокировки»](#консистентность-и-блокировки) и запреты в `spec.md` §3.2, §4.1, §5.1, §5.2);
  - операция блокируется на backend;
  - игнорирование невозможно без явного подтверждения в UI; фиксация в audit.
- Уведомляются команды-владельцы исходного и целевого компонента; при cross-unit — с учётом публичности.
- Система должна уметь показать затронутые **компоненты, приложения, фичи, сервисы, юниты**.
- При **`deprecated`** / **`unactive`** на используемой версии — сигнализация в UI: клик по жёлтому треугольнику открывает модалку со списками приложений, команд, компонентов, фич и услуг ([ui-spec.md §8.5](./frontend/ui-spec.md)). На текущем этапе — **только отображение** списков (без email/webhook/копирования контактов).
